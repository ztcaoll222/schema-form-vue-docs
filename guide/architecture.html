工作原理 ​

schema-form-vue 把“表单描述”和“组件实现”分开，分成三层：

text
schema（你写的字段描述）
        ↓
form 引擎（校验、状态、布局、选项加载）
        ↓
UI 适配器（把字段渲染成具体组件）
        ↓
Element Plus / Naive UI / Ant Design Vue / 原生控件

三层分别做什么 ​

schema ​

用 s.object()、s.string()、s.enum() 等声明字段。schema 里只有语义：

  • 这个字段叫什么、显示什么 label；
  • 是否必填、有什么校验；
  • 默认值、是否可见、是否禁用；
  • 用哪种输入语义（文本、数字、枚举、日期、富文本……）。

schema 不引用 Vue 组件，也不依赖具体 UI 库。

form 引擎 ​

@schemavue/form 负责：

  • 根据 schema 递归渲染字段；
  • 维护表单值、错误、touched 状态；
  • 执行校验、条件显示和联动；
  • 处理布局、数组字段、异步选项；
  • 把字段状态交给适配器。

校验和状态逻辑在这里完成，因此同一份 schema 不依赖具体 UI 组件。

UI 适配器 ​

适配器负责把抽象字段变成具体组件。例如 string 字段在 Element Plus 里是 ElInput，在 shadcn 风格里是原生 input。

适配器需要提供：

  • 基本字段组件：文本、多行文本、数字、枚举、布尔、日期；
  • 表单项容器：Form、FormItem、数组项；
  • 可选的布局和富文本能力。

因为适配器的接口是固定的，切换 UI 库时只需要换适配器，schema 和业务代码不用改。

可选能力 ​

核心包保持轻量，下面这些能力按需安装：

想要的能力安装
只读表格@schemavue/table
HTML 富文本@schemavue/tiptap
Markdown 富文本@schemavue/milkdown 或 @schemavue/tiptap-markdown
JSON Schema 互操作@schemavue/json-schema
多语言文案@schemavue/locale

不安装富文本编辑器时，富文本字段会退化为普通 textarea；不安装表格包时，表单功能不受影响。

数据流 ​

  1. 用户输入 → 适配器触发字段更新；
  2. form 引擎写入表单值并重新计算相关字段状态；
  3. 校验结果和可见性变化回到字段；
  4. 字段通过适配器重新渲染。

适配器只关心“怎么显示、怎么触发更新”，不保存业务状态；因此适配器可以替换，也可以自己实现。

自定义 ​

  • 自定义字段：为适配器增加或覆盖一个 widget；
  • 自定义布局：使用内置 grid/card/tabs/steps，或基于字段插槽自行组合；
  • 自定义编辑器：把任意实现标准字段接口的 Vue 组件接入富文本配置。

更深入的设计说明在仓库的 docs/design/ 中；日常使用不需要阅读。
